# 发卡网

自动发货的卡密商城:分类商品展示、购物车、下单支付、支付成功后自动发卡、订单查询、后台管理。支付支持三条通道(可多选,配置都在后台「支付」里):

1. **支付宝当面付** — 直连支付宝开放平台,预下单生成二维码,异步通知发货;
2. **微信免签** — 个人收款码 + 监听软件回调,无需商户号;
3. **易支付** — 兼容易支付 V1 协议(MD5 签名)的聚合网关。

## 功能

- 店铺首页:分类、商品卡片(库存、价格、推荐)、公告
- 商品页:详情、邮箱、数量、支付方式、立即购买 / 加入购物车
- 购物车:多商品合并成一个订单支付
- 付款页:当面付/免签显示二维码,状态轮询、我已支付查询
- 发货方式:每个商品可设自动发货或手动发货,前台商品卡片上和库存一起显示;手动发货商品付款后等商家在后台点发货
- 订单页:状态轮询、继续支付、主动查单、卡密展示与复制
- 查订单:订单号 / 邮箱 / 本机订单
- 后台(`/admin`):概况统计、分类、商品、卡密批量导入、订单(查单/手动发货/取消释放卡密)、**支付设置**、店铺设置
- 支付安全:回调验签、金额核对、幂等发货(重复通知不重复发卡)、库存事务内复查防超卖

## 一键安装(推荐)

在服务器上运行,脚本会装 Docker(如果没有)、拉源码、问你要设置的后台密码和域名(直接在终端里填,不用改文件)、启动服务:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/qwetcn/fakawang/main/install.sh)
```

已经下载/解压了源码的话,直接在源码目录里运行 `./install.sh` 也一样。常用操作:

```bash
./install.sh --update           # 更新到最新版并重启
./install.sh --reset-password   # 重新设置后台密码并重启(不用改文件)
./install.sh --non-interactive  # 无人值守安装(密码自动生成并打印)
```

> 装好后打开后台 `/admin`,在「支付」页里配置支付通道就能开店。域名与 HTTPS、备份、更新的详细步骤见《部署教程.md》。

## 手动安装(Docker)

```bash
cp .env.example .env
# 编辑 .env:可填 ADMIN_PASSWORD(不填则首次启动自动生成,见日志或 data/.admin_password)
docker compose up -d --build
```

本机验证 `curl http://127.0.0.1:8000/api/health`;公网访问需配反代(见《部署教程.md》)。后台在 `/admin`,支付在后台「支付」页里配置。

## 不用 Docker

```bash
cp .env.example .env   # 改好配置
sh run.sh              # 首次运行自动建虚拟环境并装依赖
```

## 支付配置(后台「支付」页)

### 1. 支付宝当面付

1. 登录支付宝开放平台,创建应用,开通「当面付」产品(个人可开通,按平台要求完成认证)。
2. 在应用的「密钥管理」里设置应用公钥(用支付宝密钥生成器生成 RSA2 密钥对,把应用公钥贴进去),平台会返回一个「支付宝公钥」——注意是**应用维度的支付宝公钥**,不是平台总公钥。
3. 在后台「支付」页填:AppID、应用私钥(PEM 全文,含 BEGIN/END 行)、支付宝公钥,勾选启用并保存。保存时程序会校验密钥格式,格式不对会报错。
4. 异步通知地址(`你的域名/pay/alipay/notify`)由程序在下单时自动传给支付宝,无需在平台填写;但支付宝必须能公网访问到你的域名,建议上 HTTPS。
5. 测试可用沙箱:把网关地址改成 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`,用沙箱应用的凭证。

### 2. 微信免签

1. 准备你的微信个人收款码:在微信里打开收款码,把码解析出的链接(如 `https://wx.tenpay.com/...` 或 `wxp://...`)填进后台「收款码内容」;或者把收款码图片传到图床,填图片地址。
2. 后台会生成一个回调密钥,把它填进你的监听软件。
3. 监听软件(需你自己部署在手机或电脑上并保持在线)检测到微信到账后,向回调地址 POST JSON:

```json
{"amount": "12.28", "paid_at": "2026-11-15 02:50:00", "payer": "买家昵称", "txid": "4200001234", "out_trade_no": "FK...", "sign": "hmac_sha256_hex"}
```

签名方法:剔除 `sign` 与空值,按参数名排序拼成 `k=v&k=v`,用回调密钥做 HMAC-SHA256,结果小写 hex。`out_trade_no` 有就按订单号+金额核对;没有就按金额在窗口内(默认 30 分钟)匹配唯一的待支付订单;金额相同有多笔时不自动发货,需后台手动发货。`txid` 用于去重,建议传微信支付单号。

4. 监听软件掉线期间的收款不会自动发货,买家可联系你手动处理;后台订单里可点「手动发货」。

### 2b. 通知转发(短信转发器,推荐新手用)

不想用专用监听软件时,可用开源免费的 SmsForwarder(短信转发器)监听安卓通知栏:它把微信收款提醒转发到本店的 `/pay/forward/notify` 接口,本店解析金额后按金额匹配发货。鉴权用同一个回调密钥,放在 URL 参数 `?key=...`、请求头 `X-Callback-Key` 或 JSON/表单字段 `key` 里均可;接口接受 JSON、表单、URL 参数与原始文本,字段名兼容 title/msg/content/package 等。详细步骤见《监听部署教程.md》。

### 3. 易支付

在你的支付平台拿到网关地址、商户 ID、商户密钥,填进后台「支付」页的易支付区,勾选启用。`支付方式`里写网关支持的类型代码,如 `alipay:支付宝,wxpay:微信支付`。异步通知与同步跳转地址由程序在下单时自动传给网关,无需在网关后台填写。

`.env` 里的 `EPAY_*` 只在第一次启动时导入后台做初始值,之后改配置一律去后台,改 `.env` 不会再生效。

## 邮件通知(手动发货提醒)

后台「通知」页可配:手动发货商品的订单付款后,自动发邮件提醒你去后台发货。

- 填收件邮箱 + SMTP 服务器/端口/加密方式/账号/密码,点保存,再点「发送测试邮件」验证。
- QQ/163 邮箱的密码栏填授权码(不是登录密码);Gmail 填应用专用密码。
- 未付款的订单不发邮件;同一订单只发一次;邮件发不出去不影响订单和支付,配置好后下一单会重新触发。

## 上货流程

1. 登录后台 → 分类:新建分类(如「账号专区」)。
2. 商品:添加商品,填价格和详情(写清卡密格式与售后说明),选发货方式:自动发货(付款后立刻发卡)或手动发货(付款后订单等你后台点发货再发卡;前台会显示「手动发货」)。自动发货需要先导入卡密,库存为 0 时不能下单;手动发货不用提前导卡密也能卖,付款后在订单详情里现填发货内容(一行一条),填了就按填的发,不填则按库存分配。
3. 卡密:选中商品,批量粘贴卡密,每行一条。库存 = 未售出的卡密条数,卖完自动显示缺货。
4. 设置:改店铺名、公告、客服链接、使用教程。

## 不接支付也能测试

没配任何支付通道时前台下单会提示未配置。测试发卡流程:先在 `.env` 设 `DEMO_SEED=1` 首次启动写入演示数据(正式开店前删库并改回 0),或直接在后台建商品和卡密;然后到后台订单里对测试订单点「手动发货」验证卡密分配。正式收款务必配好支付通道。

## 安全提醒

- 上线前请确认后台密码已设置(见 .env 说明),并用 HTTPS。
- 应用私钥、支付宝公钥、商户密钥、回调密钥只保存在服务器数据库里,不要发给任何人、不要提交到公开仓库。后台显示时密钥只露尾号,留空提交表示不修改。
- 数据库在 `data/shop.db`,定期备份该文件(连同 `data/.secret`)。

## 常见问题

- **支付成功但没发卡?** 先看订单页状态;点「我已支付,查询结果」(当面付/易支付会主动查单,免签靠监听回调)。仍不行:检查服务器时间、支付方能否访问你的回调地址。
- **当面付提示签名校验失败?** 多半是「支付宝公钥」填错(填成了应用公钥或平台总公钥),或应用私钥与平台上设置的不匹配,核对后重新保存。
- **免签收了款没发货?** 检查监听软件是否在线、回调密钥是否一致、回调地址能否访问;金额相同有多笔订单时系统会拒绝自动发货,去后台手动发货。
- **部署教程在哪里?** 压缩包里的《部署教程.md》:Docker/直接运行、域名 HTTPS、备份与更新都在里面。
- **手动发货商品付款后买家看不到卡?** 正常:订单状态是「待手动发货」,你去后台订单详情,在「手动发货内容」框里填入要发的东西(一行一条),点「手动发货」后买家就能看到;不填内容时按库存分配。
- **库存显示 0?** 卡密没导入或已售完,去后台卡密里补充。
- **订单金额与支付方不一致被拒?** 改价后旧订单仍按原价核对,属于正常保护;让买家重新下单。
